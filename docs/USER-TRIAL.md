# MVP 试用：验证使用价值

**当前状态：尚无真实用户试用记录。** 下列是拟验证的目标和记录表，不是已完成的调查。
自动化测试不能替代真人使用反馈；也不要求为报名编造用户、访谈或节省时间的数据。

## 目标用户与假设

目标用户：已有 MoonBit 环境、需要从连续标量模型反求参数的开发者。
拟验证的问题：能否在自己的应用中引入这个库，改变函数，并正确区分可信候选结果、
迭代预算不足和输入错误？终止诊断是否帮助其决定接受结果、改区间还是调整预算？

## 一次短试用

准备：给试用者仓库链接与 [独立接入说明](CONSUMING.md)，从已安装工具链开始。
安装编译器耗时单独记录，不混入首次调用时间。

1. 独立运行 consumer 示例，找到 `x³−2=0` 的结果与停止原因。
2. 将回调改为 `x³−8=0`，区间改为 `[1,3]`，确认根约为2。
3. 设 `max_iterations=0`，说明为什么返回 `Ok` 仍不能当作收敛成功。
4. 改为 `x²+1=0`、区间 `[-1,1]`，解释 `NoSignChange` 与上一步的区别。
5. 指出下一次自己的实际模型能否使用该库，以及最阻碍采用的一点。

## 我们设定的判定标准（不是赛事规定）

- 首次接入和换函数目标为10分钟内完成；实际时间待记录。
- 两个正常求解任务均得到正确结果，两个失败场景均解释正确。
- 无需修改库内部代码；记录全部人工提示、环境失败及绕行步骤。
- 至少收集一名非本次实现者的实际反馈，再决定下一轮改进；这只是一轮早期学习，
  不能据此宣称市场需求已被充分证明或已有付费客户。

若接入失败，优先修环境/文档；若误用 `Ok`，优先改诊断示例；若没有适用的实际模型，
先调整用户与问题定位。新算法、更多后端和额外页面按反馈决定优先级。
